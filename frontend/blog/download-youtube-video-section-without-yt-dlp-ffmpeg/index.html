How to Download a Specific Section of a YouTube Video (Browser vs. yt-dlp & FFmpeg)

Published by YTCuttr Team • Updated November 26, 2026 • 8 min read
TL;DR — CLI vs. Cloud Browser Use yt-dlp --download-sections "*START-END" --force-keyframes-at-cuts when automating batch downloads on a desktop terminal or grabbing clips longer than 5 minutes. Use YTCuttr.com when you are on mobile (iPhone/Android), want an interactive preview player to pinpoint timestamps visually, or want 1-click 1080p/4K MP4 and WAV/MP3 cuts without installing Python or FFmpeg.

Developers and power users across GitHub Gists, r/DataHoarder, and r/VideoEditors rely heavily on yt-dlp and FFmpeg to pull exact time slices from long videos without wasting bandwidth on a multi-gigabyte file. Both tools are brilliant—when you are sitting at a properly configured desktop terminal.

When you are on an iPhone, Chromebook, or locked-down office machine—or simply don’t want to debug signature cipher updates—a browser-based cloud cutter gets you the exact same segment in seconds. Below is the complete technical breakdown of both approaches.

Method 1: The Command-Line Way (yt-dlp + FFmpeg)

Make sure both yt-dlp (updated to the latest release) and ffmpeg are installed in your system PATH. Without FFmpeg, yt-dlp cannot merge separate 1080p/4K video and audio streams or seek cleanly inside a range.

1. Download a Frame-Accurate MP4 Section

yt-dlp --download-sections "*00:01:30-00:03:00" \ --force-keyframes-at-cuts \ -f "bv*[ext=mp4]+ba[ext=m4a]/b[ext=mp4]" \ -o "clip_%(id)s.mp4" \ "https://www.youtube.com/watch?v=VIDEO_ID"

Why --force-keyframes-at-cuts matters: By default, FFmpeg cuts on the nearest keyframe (which on YouTube can be 2–5 seconds apart). Adding --force-keyframes-at-cuts tells FFmpeg to re-encode the boundary frames cleanly so your clip doesn’t start with frozen video or out-of-sync audio.

2. Download Only an Audio Section (WAV or 320kbps MP3)

yt-dlp --download-sections "*00:05:10-00:06:00" \ -x --audio-format wav \ "https://www.youtube.com/watch?v=VIDEO_ID"

3. Trim an Already-Downloaded Local Video with FFmpeg

If the full MP4 is already on your drive, always put -ss before -i for fast input seeking:

# Fast stream copy (cuts at nearest keyframe) ffmpeg -ss 00:01:30 -to 00:03:00 -i full_video.mp4 -c copy trimmed_clip.mp4 # Exact frame-accurate cut (re-encodes cleanly) ffmpeg -ss 00:01:30 -to 00:03:00 -i full_video.mp4 -c:v libx264 -crf 18 -c:a aac exact_clip.mp4

Where the CLI Workflow Breaks Down

  • Zero native iOS / mobile workflow: Running Python, yt-dlp, and FFmpeg binaries on iPhone or standard Android Chrome is impractical for quick clips.
  • Frequent YouTube extraction updates: When YouTube rotates player JS or streaming protocols, older yt-dlp installs throw 403 errors until you update (yt-dlp -U).
  • Blind timestamp guessing: You still have to open YouTube in another window, scrub manually, write down timestamps, and type them into a shell command.

Frequently Asked Questions

Why does yt-dlp --download-sections sometimes include extra seconds or black frames?

Without --force-keyframes-at-cuts, FFmpeg trims at the nearest preceding keyframe. Adding that flag forces clean boundary re-encoding so cuts start on the exact second.

What is the fastest FFmpeg command to trim an already downloaded video?

Put -ss before -i: ffmpeg -ss 00:01:30 -to 00:03:00 -i input.mp4 -c copy output.mp4. Use -c:v libx264 -c:a aac if you need frame-accurate boundaries.

Can I run yt-dlp --download-sections on an iPhone or Chromebook?

Not natively without terminal workarounds. Browser tools like YTCuttr run the extraction on cloud servers and send only the trimmed MP4 to Safari or Chrome.
